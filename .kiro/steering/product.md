## What it is

Server Familiar (Kiroween 2026, Frankenstein category, deadline
5 Dec 2026 05:00 WIB) turns each server in a fleet into a living
creature rendered as a procedurally drawn monster whose body is its
hardware. A tiny Go agent reports real metrics to a Go "lab"; the lab
derives body, mood, and behaviour from those metrics, lets familiars
perform permissioned self-care, and writes their lives — diary,
dreams, scars, deaths, reincarnations — in voices grounded in real
telemetry. The builder's real fleet (~28 Tailscale hosts, mostly
expiring trial VPS) is the inspiration: a stitched-together fleet of
borrowed machines is literally Frankenstein's creature.

## The three pillars

1. **ALIVE** — Mood / energy / hunger derived from real metrics with
   smoothing. RAM = body size, CPU = fever, disk = stomach,
   bandwidth = appetite, uptime = age. Growth stages I → II → III.
   Incidents leave **permanent scars**; every resurrection adds
   **+1 stitch**.
2. **ACTS** — Self-care from a strict action allow-list (restart a
   known service, clear caches, health ritual), executed by the agent
   under per-familiar permission: **Auto** or **Ask-first** (lab +
   Telegram approval). Everything logged.
3. **TALKS** — Diary, dreams, and chat generated by the lab, grounded
   in the familiar's real metrics and events, plus an **MCP server**
   (`list_familiars`, `how_is`, `fleet_mood`) so AI assistants can ask
   the fleet how it feels.

## The nine living features (checklist)

- [ ] Reincarnation on migration (soul-orb ceremony, past-lives timeline)
- [ ] Guard senses (unknown-IP growl, failed-login door scratches, port-scan bark)
- [ ] Take for a run (speedtest-as-play, personal records)

- [ ] Adoption certificate + Life Book PDF export

## Demo mode is a hard requirement

The lab must run a **simulated 6-familiar fleet** (the six above) with
no real servers enrolled, demonstrating every feature — including
death, migration/reincarnation, guard events, and runs. Judges will
run demo mode; if a feature cannot be shown in demo mode, it does not
count as done.

## Tone rules for generated text (diary, dreams, chat, epitaphs)

- **In-character, always.** Each familiar speaks as itself, with the
  character implied by its species and history (Anls is unbothered and
  slow; Alpi is small and wondering; Hermuse is stitched and earnest).
- **Grounded in real metrics, always.** Every factual claim in
  generated text must trace to actual samples or events passed in the
  prompt context. Fever means measured CPU. A death means a real
  downtime/migration event.
- **Never invent metrics.** Do not fabricate numbers, incidents,
  neighbours, or history that the context does not contain. If the
  data is thin, be brief or be poetic about the weather — never make
  up telemetry.
- Short by default. A diary entry is 2–5 sentences. Dreams are a short
  paragraph. Chat answers are conversational, not reports.
- English for all generated content in this build.
